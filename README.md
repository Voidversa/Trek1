# Найди команду

Автор проекта публикует вакансии, кандидаты подают заявки, автор принимает или отклоняет. Все обязательные функции Н01–Н10 и правила раздела 3 реализованы на сервере.

**Стек:** Python 3.9+ (только стандартная библиотека), SQLite, одностраничный интерфейс на чистом JS. Устанавливать ничего не нужно.

## Запуск
```
python app.py            # http://localhost:8000 (при первом запуске создаёт БД с демо-данными)
python app.py reset      # восстановить исходный набор данных (остановите сервер перед этим)
python -m unittest -v    # автоматические тесты
```
Порт: `PORT=9000 python app.py`. Файл БД: `data.db` (или `DB_PATH`).

## Схема данных
```
users(id, email*, pw, name, bio, skills, interests)      sessions(token, user_id)
projects(id, author_id→users, title, description, goal, category, published, open, created_at)
vacancies(id, project_id→projects, role, skills, description, seats>=1)
applications(id, user_id, project_id, vacancy_id, message, status, created_at)
   уникальный индекс (user_id, project_id) WHERE status='pending'   -- одна активная заявка
members(id, project_id, vacancy_id, user_id, application_id*, UNIQUE(project_id, user_id))
```
Свободные места не хранятся счётчиком: свободно = `seats − count(members)`, рассинхрона нет.

## Как обеспечены правила
- Изменения идут в транзакции `BEGIN IMMEDIATE`: проверка места, добавление участника и смена статуса заявки атомарны, параллельные принятия на последнее место сериализуются.
- Права проверяются на сервере в каждом запросе; интерфейс лишь скрывает кнопки.
- Одна ожидающая заявка гарантируется и проверкой, и частичным уникальным индексом БД. Повторный запрос возвращает 409.
- Сообщения кандидатов отдают только `/projects/:id/applications` (автору) и `/my/applications` (самому кандидату).

## Тесты (`test_app.py`) и что каждый ловит
| Тест | Неисправность, которую обнаруживает |
|---|---|
| `Rights.test_only_author_processes` | заявку обрабатывает не автор (посторонний или сам кандидат) |
| `Rights.test_foreign_edit_and_applications_forbidden` | правка чужого проекта, чтение чужих заявок, заявка автора в свой проект |
| `OnePending.test_single_active_application` | вторая активная заявка через повтор или другую вакансию |
| `OnePending.test_reapply_after_reject_keeps_history` | потеря истории или запрет повторной подачи |
| `Capacity.test_last_seat_sequential` | принятие второго кандидата на последнее место |
| `Capacity.test_last_seat_concurrent` | гонка двух одновременных принятий (потоки, отдельные соединения) |
| `Capacity.test_repeat_accept_no_duplicate` | дубль участника и второе занятое место при повторном принятии |
| `Capacity.test_seats_not_below_accepted` | уменьшение мест ниже принятых, удаление вакансии с данными |
| `Closed.test_closed_blocks_apply_and_accept` | подача и принятие при закрытом наборе; потеря заявок при закрытии |
| `Validation.test_bad_input_rejected` | пустые поля, пробелы, места 0 / −1 / 1.5 / строка, публикация без вакансий |

## Известные ограничения
- Обновление данных только перезагрузкой страницы (по условию). Чата, уведомлений, выхода из состава и функций раздела 9 нет.
- Сессии без срока жизни, нет HTTPS и CSRF-токенов (локальный запуск). Каталог фильтруется в Python, рассчитан на сотни проектов.
- Автотестов интерфейса нет: он проверялся вручную и запросами к API.
